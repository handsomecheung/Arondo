# Arondo v0.2.13

**Release Date:** 2026-07-25
**Commits:** 5
**Tag:** v0.2.13

An HTTP automation API for driving Arondo from scripts, a project-level three-dot menu (File Browser, Open Terminal, Show Changes), and a reworked project-readiness gate that lets sessions queue multiple follow-up todo messages without blocking the chat input.

---

## Highlights

- **Automation API**: New `GET /api/sessions/{id}` status-polling endpoint, plus a `tempDir` option on session creation that generates a fresh temp directory on a runner (via a new `fs.mkdtemp` runner method) with random runner selection when no `runnerId` is given. The default `agentType` for new sessions is now `auto`. Documented in the README with a stdlib-only Python example (`examples/session_automation_demo.py`).
- **Project Three-dot Menu**: The Project Page header gained a three-dot menu with File Browser, Open Terminal, and Show Changes entries; Delete Project moved into the menu as the last item. "Show Changes" is a sessionless visual diff of the project's working tree, backed by new `GET /api/projects/[id]/git-status` and `GET /api/projects/[id]/diff` routes, and is disabled with "No Changes" when the tree is clean.
- **Multiple Queued Follow-ups**: Sessions can now carry more than one queued `user-todo` follow-up message at a time. The dirty/busy confirmation gate now only applies to a session's very first message (mirroring session creation); later follow-ups only check the session's own running state and whether a todo is already queued ahead of them. The chat input is no longer force-disabled while a draft/pending todo exists, so users can keep composing.
